# БД Restrict: логическая ER-модель

**Дата:** 14.07.2026  
**Предшественник:** [01-domain.md](01-domain.md)

## Диаграмма

```mermaid
erDiagram
  ListType ||--o{ UploadBatch : "has"
  ListType ||--o{ SpecialCase : "has"
  UploadBatch ||--o| SpecialCase : "may_link"
  SpecialCase ||--|{ SpecialCaseItem : "contains"

  ListType {
    int ListTypeId PK
    string Code UK
    string Name
    string FolderSegment
    string RoutingKeySuffix
    bool IsActive
  }

  UploadBatch {
    guid UploadBatchId PK
    guid CorrelationId UK
    int ListTypeId FK
    string OriginalFileName
    string StoredFilePath
    string UploadedBy
    datetime UploadedAt
    string NotifyStatus
  }

  SpecialCase {
    guid SpecialCaseId PK
    int ListTypeId FK
    guid UploadCorrelationId "nullable"
    string AccessTokenHash
    string Status
    datetime ExpiresAt
    string SourceFilePath
    datetime CreatedAt
    string CreatedBy
    datetime ResolvedAt "nullable"
    string ResolvedBy "nullable"
  }

  SpecialCaseItem {
    guid SpecialCaseItemId PK
    guid SpecialCaseId FK
    string FieldCode
    int RowNumber "nullable"
    string RawValue
    string ParserMessage
    string UserValue "nullable"
    bool IsRequired
    int SortOrder
  }
```

## Кардинальности

| Связь | Кардинальность | Комментарий |
| --- | --- | --- |
| ListType → UploadBatch | 1:N | Много загрузок одного типа |
| ListType → SpecialCase | 1:N | |
| UploadBatch → SpecialCase | 0..1 : 0..N | Связь мягкая по `UploadCorrelationId` (не жёсткий FK на MVP допустим) |
| SpecialCase → SpecialCaseItem | 1:N | Хотя бы 1 item при создании кейса |

## Примечание по FK UploadBatch ↔ SpecialCase

На MVP связываем логически через `UploadCorrelationId = UploadBatch.CorrelationId` **без обязательного FK**, чтобы парсер мог создать кейс даже если UI не писал `UploadBatch` или correlation потерян. Усиление до FK — после стабилизации контура.
